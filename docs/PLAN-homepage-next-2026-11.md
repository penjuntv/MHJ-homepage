## 1. MotionSites 스킬에서 배운 것

스킬의 실체: 실행 코드는 스크린샷 스크립트 1개(`shoot.py`)뿐이다. 나머지는 지침 문서와, 유료 상품 홍보용 예시 프롬프트 40개·영상 50여 개다. 대상은 SaaS·에이전시의 "영상 배경 첫 화면"이다. 라이선스는 지침·스크립트 = MIT, 예시·영상 = © MotionSites(재배포 금지). **우리는 아이디어만 가져와 우리 말로 새로 쓴다**(고지 의무 없음).

| 요소 | 판정 | 우리 식으로 |
|---|---|---|
| 페이지마다 숫자로 쓴 설계서 | **들임(핵심)** | 13칸 중 7칸만: 요약(이 페이지가 기억될 한 가지) · 글꼴 표 · 색(=`globals.css` 변수만) · 첫 화면 요소 표 · 움직임 표 · 반응형 표 · 금지/필수(반지름 ≤12px · 변수만 · 실명 0 · 다크 모드) |

## 2. "최상급"의 기준 — MHJ 지면 점수표

**기계가 재는 것(하나라도 걸리면 탈락)**: 페이지 JS 오류 0 · 실패한 요청 0 · 가로 넘침 0 · 깨진 이미지 0 · 대비 4.5:1 미만 0 · axe 위반 0 · 제목 글꼴 대체(폴백) 0 · 흰 화면 깜빡임 0 · 실명 0 · 모바일 LCP < 2.5초 · CLS < 0.1.

**사람 눈으로 매기는 10항목(1~10점)** — 스크린샷(데스크톱 1440·태블릿 768·모바일 390, 라이트·다크)을 보고 매긴다.

| # | 항목 | 묻는 것 |
|---|---|---|
| 1 | 3초 첫인상 | 누구의 무엇인지 3초 안에 아는가 |
| 2 | 편집 위계 | 먼저 볼 것 → 다음 볼 것이 하나로 읽히는가 |
| 3 | 글자 | 크기 비율·자간·줄 길이(28~42rem)가 맞는가, 한글이 깨지지 않는가 |
| 4 | 구성·여백 | 정렬 기준이 하나인가, 숨 쉴 여백이 일정한가 |
| 5 | 색·빛 | 강조색 1개, 다크 모드에서도 같은 위계인가 |
| 6 | 사진 다루기 | 가족 사진이 잘 잘렸는가, 글자와 겹치지 않는가 |
| 7 | 읽기 편함 | 본문까지 손이 덜 가는가(MotionSites 의 "움직임" 자리) |
| 8 | 모바일 | 손가락 하나로 다 되는가 |
| 9 | 문구 | 꼬리표·버튼 말이 사실과 맞는가("Waitlist" 같은 틀린 말 0) |
| 10 | 마감 | 줄 끝·간격·정렬의 작은 어긋남 |

**통과선: 평균 8점 이상, 7점 미만 항목 없음.** 못 넘으면 가장 약한 3개를 **숫자로**(예: "제목 자간 -0.8px → 0.02em") 고치고 다시 찍는다. 최대 3번. 점수는 Claude 가 매기되, 스크린샷과 점수를 PR 에 붙여 PeNnY 가 확인한다(스스로 매긴 점수라 객관 측정이 아니다).

### 3.3 앱 첫 화면에서 본 것

- 라이브 제품이다. 무료 첫 책 1권, 유료 요금제 2개(Stripe), 4개 언어.

- 저널로 가는 링크 0개. 글꼴·색은 저널과 다르다(앱: Fraunces·파스텔 / 저널: Playfair·흑백).

**강점**: 저널에는 앱이 갖지 못한 것이 있다 — Jin 의 실제 기록 20편(Little 15 Mins, 누적 조회 791)과 "왜 만들었나"의 이야기. 앱은 저널이 갖지 못한 것을 가졌다 — 실제로 쓸 수 있는 제품. **서로의 빈칸이 정확히 맞물린다.**
