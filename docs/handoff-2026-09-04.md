### ✅ 후속 완료 — anon 쓰기 권한 회수 (2026-09-05, 사용자 승인 후 적용)

위 항목의 "남은 관련 사항"이던 anon 쓰기 권한을 회수했다.
기록·롤백·대조군 수치는 `docs/sql/anon_blogs_revoke_write.sql`.

착수 전 실측에서 **범위가 문서보다 넓었다**: INSERT·UPDATE·REFERENCES 39컬럼
외에 테이블 레벨로 **DELETE·TRUNCATE·TRIGGER** 도 anon 에 남아 있었다.
특히 `TRUNCATE` 는 **RLS 가 적용되지 않는 명령**이라 "RLS 한 겹" 방어조차
걸리지 않는 상태였다. 승인 범위(= blogs 의 anon 쓰기 권한) 안이라 함께 회수했다.

```sql
revoke insert, update, delete, truncate, references, trigger
  on table public.blogs from anon;   -- SELECT 36컬럼은 그대로
```

적용 전후 같은 anon 키 REST 프로브 대조군 (권한 회수가 실제로 문다는 증거):

| 프로브 | 적용 전 | 적용 후 |
|---|---|---|
| `PATCH ?id=eq.-1` | **204** (권한 통과 후 RLS 로 0행) | **401 · 42501** permission denied |
| `POST` (insert) | 401 "violates row-level security" | **401** permission denied |
| `DELETE ?id=eq.-1` | (미측정) | **401** permission denied |
| `select=id,title` · 앱 컬럼 4종 | 200 | **200** (불변) |
| `select=*` · `content_backup` 등 | 401 | **401** (불변) |

무영향 확인: 라이브 `/` `/blog` `/blog/[slug]` `/feed.xml` `/sitemap.xml`
`/llms.txt` `/api/search` 전부 200 — **상세·목록은 `x-vercel-cache: MISS`,
즉 회수 이후의 새 렌더**다. `/blog` 페이로드에 blog 객체 30개.
`audit-endpoints` ✅ · `audit-name-exposure`(DB 7테이블 + 라이브 138 URL) ✅ 0건.

### 남은 것 — 나머지 58개 테이블 (미적용, 사용자 판단 필요)

같은 노출은 blogs 만의 문제가 아니었다. public 스키마 **63개 테이블 전부**가
anon INSERT/UPDATE/REFERENCES 를 갖고 RLS 로만 막힌다(Supabase 기본 posture).

## 5. 지뢰밭 — 이 프로젝트에서 실제로 밟았던 것들

1. **워크플로 run 블록**: 이슈 본문은 반드시 quoted heredoc (#32 사고). run 블록 안에는
   **주석에라도** 빈 `${{ }}` 표현식 금지 — 파싱 422 (#33 사고).
2. **락파일은 npm@10 기준**: 로컬 npm@11 은 결손 락도 통과시킨다. CI 재현은
   `npx npm@10 ci --dry-run` (#29 사고).
3. **Supabase API**: `listUsers()` 는 MFA factors 를 안 채운다(전원 0 으로 보임) —
   `admin.mfa.listFactors({userId})` 가 권위. 이걸 믿고 계정을 지웠다 복구한 사고 있음.
   존재하지 않는 컬럼 select 시 **쿼리 전체가 조용히 null** — `data ?? []` 로 삼키면
   테이블 통째 누락 (감사 스크립트 og_image 사고). RPC 인자명은 `days`/`lim`.
   **`blogs` 의 anon 정책은 SELECT 하나뿐**(`anon_select_published_blogs`) — anon 으로는
   UPDATE 가 조용히 0행이다. 그래서 서버 라우트를 `createAdminClient()` 로 바꾸면
   **RLS 가 막아주던 쓰기가 갑자기 살아난다**(#38 의 ai-insight 사고).
4. **매거진**: 템플릿에 `cqh`/`vh` 금지 (mag-unit-guard 훅이 차단, 사유는
   `docs/MHJ_MAGAZINE_DESIGN_BIBLE.md` §cqh). 세로 비율은 `calc(N * var(--mag-cqh))`.
   리딩 뷰어 검증 URL 에 **`?page=1` 필수** — 없으면 이슈 상세(썸네일)가 열려 오판.
   `?page=N(≥3)` 은 슬러그 URL 로 308 리다이렉트된다.
5. **감사 로직 — 위음성 3종**: 텍스트 매칭은 반드시 case-insensitive (i 플래그 누락 →
   NO_GEO 32 오탐 사고). **HTML 을 대상으로 키워드를 세지 말 것** — 마크업 속 URL
   (`mhj.nz`)이 본문 키워드로 잡혀 no_geo 22편이 4편으로 보였다. **Postgres 정규식의
   단어 경계는 `\y`** — `\b` 는 백스페이스라 `'<h2\b'` 가 조용히 0을 돌려준다(JS 는 `\b`
   가 맞다). 셋 다 "결과가 정상으로 보이는" 위음성이라 눈에 안 띈다 —
   **감사 스크립트는 위반을 주입해 exit 1 을 실증할 것.**
   실명 패턴은 name-guard 훅에 걸리므로 **코드포인트 인코딩**으로 다룬다
   (`audit-name-exposure.mjs` 방식). public repo CI 로그에 실명 원문 출력 금지 — [라벨] 치환.
   SEO 판정 로직은 `.claude/skills/seo-audit-runner/SKILL.md` 의 SQL 과
   `scripts/audit-seo-regression.mjs` 가 **한 쌍** — 한쪽만 고치면 주간 게이트와
   분기 보고서가 다른 답을 낸다.
6. **이미지**: 공개 페이지 `<img>` 는 원본 직결 금지 — `lib/image-url.ts` 경유.
   width 는 next.config 의 128/256/384/640/1080/1920 만 유효(그 외 400).
7. **훅 5종 가동 중**: safety-gate(Bash: git add -A·force push 등 차단) · scope-guard ·

### B. seo-audit-runner SKILL.md 동기화 — PR #39

`SKILL.md` 의 SQL 이 옛 오탐 구조로 남아 주간 게이트와 분기 보고서가 다른 답을 냈다.

- **GEO 오탐**: 원문 HTML 에서 키워드를 찾아 `href="...mhj.nz..."` 의 `nz` 가
  지역 신호로 집계됐다 → 보이는 텍스트 기준으로 **no_geo 4 → 22편**.
  이 오탐은 내부링크를 늘릴수록 커진다(ORPHAN 정비가 GEO 개선처럼 보인다).
- **Postgres `\b` 오류**(이번에 발견): `'<h2\b'` 가 아무것도 매치하지 않아
  h1/h2 카운트가 항상 0 이었다 → `\y` 로 수정. H2 0개 11편, no_h2 6편.
  초기 서술 "52편 전부 H2 0개"는 이 버그의 산물일 수 있다.
- ALT/ORPHAN/H1 판정에 `info_block_html` 포함, 단어 수·H2 는 본문만 — 대상 구분을 표로 명시.
