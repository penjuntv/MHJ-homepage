## Q1 · Google Search Console

속성: `https://www.mhj.nz/`

> ⚠ 먼저 확인할 것: 코드에 **google verification 토큰이 두 개** 있다 — `app/layout.tsx:54` (`kjz6IsQn0jw…`) 와 `app/(public)/layout.tsx:12` (`qC-Rqu96p3i…`). GSC 속성이 둘일 수 있다. **어느 속성이 살아 있는지 먼저 알려 주세요.** 데이터가 둘로 갈려 있으면 둘 다 필요합니다.

내보내기 절차:

1. **성과 보고서** — 좌측 `실적 → 검색결과` → 우상단 기간을 **16개월**로 → 하단 탭 4개(**쿼리 / 페이지 / 국가 / 기기**)를 각각 열고 우상단 **⤓ 내보내기 → CSV 다운로드**. 총 4개 파일.
   - 그래프 위 체크박스 4개(**클릭수·노출수·평균 CTR·평균 게재순위**)를 **전부 켠 상태**로 내보내 주세요. 기본은 2개만 켜져 있습니다.
2. **페이지 색인 생성 보고서** — 좌측 `색인 생성 → 페이지` → 화면 전체 스크린샷 1장(색인됨 N / 색인되지 않음 N + 사유 표). 사유 표에 **"robots.txt에 의해 차단됨"** 또는 **"색인이 생성되었으나 robots.txt에 의해 차단됨"** 행이 있으면 그 행을 클릭해 URL 목록도 캡처해 주세요 → F-A-05(태그 페이지) 판정에 직결됩니다.
3. **Core Web Vitals** — 좌측 `환경 → Core Web Vitals` → 모바일·PC 각 스크린샷. "데이터 부족" 이면 그 화면 그대로 주세요(그것도 답입니다).
4. **Sitemaps** — 좌측 `색인 생성 → Sitemaps` → 제출된 사이트맵 목록과 "검색된 페이지" 수 스크린샷.
5. **수동 조치 / 보안 문제** — 좌측 `보안 및 수동 조치` 두 항목 스크린샷.

왜 필요한가: 이 조사에서 **색인 URL 수·실제 노출 쿼리·CTR 을 하나도 못 쟀다.** WebSearch 의 `site:` 연산자는 신뢰할 수 없는 결과를 줬다(mhj.nz URL 2개 + 무관한 위키피디아 8건).

## Q2 · 네이버 서치어드바이저 — **가장 중요**

`searchadvisor.naver.com` → 웹마스터도구

1. **사이트가 등록돼 있습니까?** (`https://www.mhj.nz` 가 목록에 있는지 예/아니오)
2. 등록돼 있다면 아래를 각각 스크린샷:
   - **요약** 화면 (사이트 진단 + 수집 현황)
   - `요청 → 사이트맵 제출` — 제출 목록과 **"가져온 URL 수"**
   - `요청 → RSS 제출` — 제출 여부
   - `검증 → 사이트 간단 체크` 실행 결과
   - `현황 → 수집 현황` · `현황 → 사이트 최적화`
   - `현황 → 검색 노출/클릭 현황` (최근 1개월)
3. 등록돼 있지 않다면 — `docs/naver-quickstart-10min.md` 의 7단계를 그대로 하시면 됩니다. 소유확인 HTML 태그는 **이미 사이트에 심겨 있어서** 등록 즉시 통과합니다. 코드 변경 0. 소요 10분.

왜 필요한가: 6일간 **네이버 유입 0건**입니다. 코드 측 준비물(인증 메타·Yeti 허용·sitemap·RSS)은 전부 완료돼 있는데 콘솔 등록 기록이 어디에도 없습니다. 등록이 안 돼 있다면 **이것 하나가 이번 조사에서 회수가 가장 큰 작업**입니다.

## Q8 · 전략 결정 (플랜 단계에 반드시 필요)

### ① 1순위 독자는 누구입니까?

| 선택지 | 그러면 달라지는 것 |
|---|---|
| **A. 뉴질랜드 거주 한인 가족** | 네이버 등록·한국어 요약이 최우선. 지금 언어 불일치(F-A-01)를 한국어 쪽으로 푼다 |
| **B. 한국 거주 예비 이민·유학 가족** | A 와 같되 "가기 전에 알아야 할 것" 축의 새 글이 필요 |
| **C. 영어권/뉴질랜드 현지 독자** | `lang="en-NZ"` 로 정정하고 구글·Bing 에 집중. 네이버 투자를 접는다 |
| **D. 기록 자체가 목적, 노출은 부수적** | 이 보고서의 P0 대부분이 P2 로 내려간다 |

**이 답이 없으면 F-A-01(언어 신고 불일치)의 처방을 고를 수 없습니다.** 지금 사이트는 본문이 영어인데 `lang="ko"` 라고 신고하고 있어서 어느 쪽에도 최적화돼 있지 않습니다.

### ② 글 제목을 바꾸거나 병기해도 됩니까?

- 발행 80편 중 제목에 한글이 있는 글 **0편**, 지역 키워드가 있는 글 **5편**, 30자 미만 **53편**입니다.
- 세 가지 선택지:
  - **(가)** 제목은 그대로 두고 `blogs.seo_title` 컬럼을 새로 만들어 **검색용 제목만 따로** 관리 — 지면의 감성 제목(`The Word Cards`)을 전혀 건드리지 않습니다
  - **(나)** 대괄호 접두(`[Y1] …` 21편)를 접미로 옮겨 앞 30자에 키워드가 오게 — 제목 문구 자체를 편집
  - **(다)** 손대지 않음

### ③ 네이버 블로그 등 외부 채널에 요약본을 배포할 의향이 있습니까?

네이버는 자기 플랫폼(블로그·카페·포스트)을 검색 상단에 우선 노출합니다. 외부 사이트가 웹문서로 상위에 뜨기는 구조적으로 어렵습니다.
- 있다면: 주 1편 한국어 요약 + 원문 링크. **운영 부담이 지속적으로 발생**합니다.
- 함께: **네이버 키워드도구 데이터**를 뽑아 주실 수 있습니까? 구글 자동완성으로는 한국어 시드 15개 중 11개가 0건이 나와서 클러스터 설계 근거가 부족합니다.

### ④ 발행 게이트를 도입해도 됩니까?

`blog-publish-preflight` 스킬을 훅으로 강제해 **답 먼저 문단 / H2 3개 / 목록·표 1개 / 내부링크 2개** 를 못 채우면 저장이 막히게 할 수 있습니다.
- 현재 80편 전부가 목록·표가 0개입니다. AI 답변 엔진 인용의 핵심 요건인데 사이트 전체에 하나도 없습니다.
- 대안: 본문은 건드리지 않고 **인포블록(정형 삽입물)에만** 목록·표를 넣는 규칙 — 두 분의 문장에 손대지 않습니다.
- 어느 쪽이 좋으십니까?

### ⑤ 주당 발행 가능 편수와, 기존 글 보강에 쓸 수 있는 시간은?

- 최근 8주 실측: **주 0.88편**
- THIN 36편 · ORPHAN 10편 · H2 0개 11편이 대기 중입니다.
- 새 글과 기존 글 보강 중 어디에 시간을 쓰시겠습니까? (예: "새 글 주 1편 + 보강 주 2편")

### ⑥ "노출"의 최종 목표는 무엇입니까?

구독 / StoryPress 전환 / 광고·제휴 / 기록 자체 — 우선순위를 매겨 주세요.
현재 구독자 15명 · 댓글 5건 · StoryPress 클릭은 **트래킹이 안 붙어 측정 불가**입니다.
