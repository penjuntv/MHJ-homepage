## 대응표

답 A = 처음 온 독자 · 답 B = 실행가 · 답 C = 반대론자 · 답 D = 원리주의자 · 답 E = 확장론자 (`sort -R` 무작위 배정)

| 자문역 | 입장 | 한 줄 |
|---|---|---|
| 처음 온 독자 (A) | 분리 | "마스터키 하나로 두 집이 열리고 한 집은 아무나 가입" — 말(실명 P0)과 구조가 어긋난다 |
| 실행가 (B) | 보류 | 이번 주 PeNnY 확인 3건(새 계정·키·지연 측정) + 분리 전환 신호 + 12/20 직후 점검일 |
| 반대론자 (C) | 분리 | 확인 안 된 완화책을 믿는 보류가 더 위험. 키 분리가 안 됐다면 11/15 전에 분리 |
| 원리주의자 (D) | 분리 | 진짜 문제는 "관리자 키가 아이 데이터에 닿는 구조". 확인 → 11/15 직후 분리 |
| 확장론자 (E) | 보류 | 다른 가족이 쓰면 그때가 분리 시점. 키 발급만으로 이유 ②가 대부분 해소(← 평가에서 오류로 지적) |

다섯 답 원문은 세션 기록에 있다. 요지는 위 표와 아래 판결에 반영됐다.

## 익명 상호 평가 요지

- 가장 강한 답: D 3표, B 2표.
- 사각지대 최대: **E 5표 만장일치** — 같은 프로젝트의 `service_role` 키는 나눠 발급해도 키마다 전 테이블을 연다. 키 정리는 교체를 쉽게 할 뿐 도달 범위를 줄이지 못한다(B·C 에도 같은 약점).
- 모두 놓친 것: 0원 조치(YuStudy 일반 가입 닫기·이름 칸 비우기), 홈페이지를 18개 표만 다루는 제한 역할로 바꾸는 중간안, 분리 실패 시 백업·롤백 기준, 10/13 구멍 재검증, 키 유출 흔적 로그 조회, 마이그레이션 실행 시각 조회.
- 근거 없음으로 걸러진 것: C "3~4일", B "30분·1시간·이틀", A "반나절"(관찰 기간 빠짐), A "구독자 명단 구멍은 이미 일어난 일"(열려 있었을 뿐 유출 근거 없음).

## 의장 판결

### 위원회가 합의한 것
- 지금의 "보류"는 사실상 방치다 — 9/14 에 지키기로 한 두 일(사용처별 키, DDL 새벽 시간대)이 확인되지 않았다.
- 이번 주에 싸게 끝낼 확인(9/14 이후 계정의 정체, 키 실제 발급 여부)이 판결보다 먼저다.
- Q4 마감 앞으로 끌어오지 않는다.
- 9/14 의 전제("가족만 쓴다")가 10/13 구멍으로 흔들렸다.

### 위원회가 갈린 것
- **지금 분리를 결정할까, 신호를 기다릴까.** 분리 쪽(A·C·D)은 "관리자 키가 아이 데이터에 닿는 구조 자체"와 RLS 한 줄 실수 위험(YuStudy 구조 변경 36건)을, 보류 쪽(B·E)은 10/13 로 급한 구멍은 막혔고 마감 사이 분리가 가족에게 비싸다는 점을 든다. 갈리는 이유: "아직 사고가 없다"를 증거로 보느냐, "지키기로 한 일이 확인조차 안 됐다"를 증거로 보느냐.
- **언제.** D 는 11/15 직후(평가: 11/30 마감·관찰 기간과 겹침), E 는 12/20 이후.

### 상호 평가에서 드러난 사각지대
- 키를 나눠도 도달 범위는 그대로 — 범위를 줄이는 길은 분리, 또는 홈페이지 전용 제한 역할뿐.
- 0원 조치(가입 닫기, 이름 칸 비우기)를 아무도 꺼내지 않았다.
- 10/13 재검증·유출 로그·마이그레이션 시각 조회, 분리 실패 대비(백업·롤백), 키 교체가 YuStudy 까지 멈추는지 — 모두 빠졌다.

### 권고
**분리(B)를 지금 결정하고, 실행은 Q4 마감 사이 빈틈에 끼운다.**
- 11/15 까지: 분리 작업 없음. 0원 조치와 확인만.
- 11/16~11/22: YuStudy 를 새 프로젝트로(새벽 한산 시간대). 옮기기 전 옛 DB 덤프. 관찰 기간엔 옛 표가 남으므로 Vercel 환경변수를 되돌리는 것이 곧 롤백(그 사이 새 기록 손실은 감수).
- 12월 첫 주: 홈페이지 쪽 정리(옛 YuStudy 표 삭제·키 교체). 12/20 마감까지 2주 여유.

이유: ① 관리자 키가 아이 데이터에 닿는 문제를 구조로 끊는 길은 분리뿐(키를 나눠도 범위 불변) ② 보류는 "규칙을 계속 지킨다"는 전제 위에 있는데 그 규칙이 확인조차 안 됐다 — 규칙을 더 얹지 말고 구조를 바꾼다(제한 역할도 같은 이유로 2순위) ③ 비용이 작고(월 $10·홈페이지 중단 0) 무거운 일은 YuStudy 쪽이라 일정만 끼우면 마감을 안 건드린다. 보류 쪽의 "신호" 목록은 "분리할지"가 아니라 "앞당길지"의 기준으로 쓴다.

### 가장 먼저 할 일 하나
**PeNnY 가 Supabase 대시보드(Authentication → Sign-ups)에서 새 가입을 끄고, 같은 화면에서 9/14 이후 생긴 계정 1개가 가족 것인지 확인한다.** 기존 계정 로그인은 유지된다. 돈이 들지 않고, 10/13 같은 구멍이 다시 열려도 들어올 사람이 없게 만드는 유일한 조치.

### 이 판결이 뒤집히는 조건
- **11/15 전에 즉시 분리:** 새 계정이 가족이 아님 · 로그에 키 유출 흔적 · 일반 가입 계정 재시험에서 10/13 구멍이 아직 열림.
- **보류가 맞아짐:** YuStudy 개발이 멈춰 구조 변경이 끊김 · 홈페이지가 이미 18개 표 전용 권한으로 돌고 있음이 확인됨.
