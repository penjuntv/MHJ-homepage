## 1. MHJ의 정체성

MHJ는 Kinfolk도 Cereal도 아니다.
- Kinfolk/Cereal은 **프로 사진가 + 프로 에디터**가 만드는 상업 매거진
- MHJ는 **가족이 직접 찍고 직접 쓰는 라이프 아카이브**

따라서:
- 너무 차갑게 절제하면 → 가족의 온기가 사라진다
- 너무 화려하게 장식하면 → 아마추어 블로그처럼 보인다
- **"따뜻하되 세련된, 감성적이되 지적인"** — 이것이 MHJ의 톤

MHJ가 추구하는 감각:
- 한국 감성의 따뜻함 + 에디토리얼 매거진의 구조적 절제
- 가족 사진의 친밀함 + 활자의 격조
- 콘텐츠의 밀도 + 여백의 여유

## 2. 레이아웃 컨테이너

### 2.1 이중 컨테이너 시스템

MHJ는 **풀-와이드(full-width)**와 **콘텐츠 영역(contained)**을 섹션 성격에 따라 병용한다.

| 용도 | max-width | 적용 대상 |
|------|-----------|-----------|
| **몰입형 섹션** | 100vw (풀-와이드) | 히어로 캐러셀, 매거진 서가, 대형 배경 이미지 |
| **콘텐츠 섹션** | 1320px | 블로그 그리드, About, 아티클 목록, 인트로 |
| **본문 읽기 영역** | 720px | 블로그 상세 본문, 매거진 아티클 본문 |

### 2.2 왜 1320px인가

- 1200px: 텍스트 중심 사이트에 적합 (Monocle, Apartamento)
- 1440px: 이미지 포트폴리오 사이트에 적합
- 1320px: MHJ는 텍스트와 이미지가 공존하고, 4열 카드 그리드에서 카드당 ~300px 확보에 최적
- 계산: 4열 × 300px + gap 24px × 3 = 1272px + padding 48px = 1320px

### 2.3 컨테이너 CSS

```css
.container-content {
  max-width: 1320px;
  margin: 0 auto;
  padding: 0 clamp(20px, 4vw, 48px);
}

.container-reading {
  max-width: 720px;
  margin: 0 auto;
  padding: 0 clamp(20px, 4vw, 32px);
}
```

### 2.4 울트라와이드 (2560px+) 대응

- 콘텐츠 영역: 1320px 유지, 중앙 정렬
- 풀-와이드 섹션: 이미지가 늘어남 — object-fit: cover로 처리
- 양쪽 남는 공간: 페이지 배경색(white/dark)

## 3. 그리드 시스템

### 3.1 반응형 열 변화

- < 640px (sm): 1열 — 모바일
- 640~1023px (md): 2열 — 태블릿
- 1024~1319px (lg): 3열 — 소형 데스크탑

- 카드 간 gap: 24px (3 × 8px 그리드)
- 섹션 간 여백: 96px (12 × 8px 그리드)
- 카드 내부 텍스트 padding: 16px (2 × 8px 그리드)

## 4. 이미지 비율

### 4.1 기본 비율 체계

| 용도 | 비율 | 이유 |

## 5. 타이포그래피

### 5.1 폰트 패밀리 (변경 없음)

- Display/Headings: Playfair Display (serif)
- Body/Label: Noto Sans KR (sans-serif)

### 5.2 크기 체계

| 용도 | 크기 | 비고 |
|------|------|------|
| **히어로 제목** | clamp(32px, 6vw, 90px) | 일반 슬라이드 / StoryPress: clamp(36px, 8vw, 120px) |
| **페이지 타이틀 (type-display)** | clamp(40px, 5vw, 56px) | --fs-display CSS 변수 |
| **섹션 제목 (type-h1)** | clamp(32px, 4vw, 48px) | --fs-h1 CSS 변수 |
| **카드 제목** | 18px (고정) | 크기 변동 없이 일정 |
| **본문** | 16px, line-height 1.7 | 한국어는 1.7이 최적 |
| **라벨/캡션** | 11px, letter-spacing 2px | uppercase, 회색 |
| **메타 정보** | 13px | 날짜, 저자 등 |

### 5.3 제목 크기 상한 원칙

- 일반 콘텐츠 제목: **56px을 초과하지 않는다** (type-display 기준)
- 히어로 캐러셀: 일반 슬라이드 **90px**, StoryPress **120px** 상한
- clamp() max값이 이 기준을 초과하는 설정 금지
- 예외: 매거진 서가의 세로 텍스트 (UI 요소이므로 별도)
- 예외: 블로그 상세 Dateline(카테고리 라벨)은 Playfair italic 300, clamp(40px, 6vw, 64px) 허용 — 매거진 chapter head UI 장식 요소로 취급

### 5.4 한 줄 글자 수

- 본문(16px): 한 줄 35~45자 (한국어 기준, 720px 읽기 영역에서 자동 충족)
- 카드 제목: 2줄 이내로 truncate

## 6. 색상 팔레트

> **정본은 `app/globals.css` 의 `:root` / `.dark` 블록이다.** 이 절은 그 값을 옮겨 적은 것이고,
> 값을 바꿀 때는 CSS 를 고친 뒤 여기를 맞춘다. 2026-09-10 W6-A 에서 실측 기준으로 전면 개정했다
> (그 전 판은 존재하지 않는 `--text-primary` · `--bg-elevated` · `--accent-light` 를 적고 있었다).

### 6.1 기본 (라이트 모드)

```css
:root {
  /* 배경 */
  --bg: #FFFFFF;
  --bg-surface: #FAF8F5;       /* 크림 — 섹션 구분, 콜아웃 */
  --bg-card: #FFFFFF;
  --bg-featured: #FAFAF8;
  --bg-warm: #F5F0EB;

  /* 글자 — `--text-primary` 는 없다. `--text` 를 쓴다 (CLAUDE.md 5) */
  --text: #1A1A1A;             /* 제목, 본문 */
  --text-secondary: #5F6E82;   /* 부제, 설명 */
  --text-tertiary: #6B7280;    /* 라벨, 메타 — 가장 옅게 쓸 수 있는 한계선 */

  /* 선 */
  --border: #F1F5F9;
  --border-medium: #E2E8F0;
  --border-strong: #E2E8F0;
  --border-tertiary: #F1F5F9;

  --accent: #4F46E5;           /* 인디고 */
}
```

### 6.2 다크 모드

`darkMode: 'class'` — `.dark` 가 같은 이름의 변수를 덮어쓴다. 컴포넌트는 변수만 쓰고,
`.dark .foo { color: #… }` 같은 수동 재정의를 새로 만들지 않는다.

```css
.dark {
  --bg: #0A0A0A;
  --bg-surface: #161412;
  --bg-card: #1E1E1E;
  --bg-featured: #111111;
  --bg-warm: #1E1A16;

  --text: #F1F5F9;
  --text-secondary: #94A3B8;
  --text-tertiary: #8B98A9;

  --border: #2E2E2E;
  --border-medium: #383838;
  --border-strong: #404040;
  --border-tertiary: #1F1F1F;

  --accent: #818CF8;           /* 인디고 원색은 어두운 배경에서 3.15:1 — 다크 전용 밝은 짝 */
}
```

**테마에 따라 뜻이 뒤집히는 변수** — 값이 아니라 *역할* 로 짝을 맞춘다. 라이트에서 쓰던 글자색을
다크에 그대로 두면 배경과 같은 색이 되는 자리가 있다.

| 변수 | 라이트 | 다크 | 비고 |
|---|---|---|---|
| `--newsletter-dark-bg` | `#2C2218` (진갈색) | `#FAF8F5` (크림) | 블록 배경이 반전된다 |
| `--newsletter-soft` / `--newsletter-muted` | `#E0DAD2` / `#BDB2A5` | `#4A3B2C` / `#6B5A48` | 위 배경 위의 글자 — **함께 반전되어야 한다** |
| `--number-accent` | `#8A6B4F` | `#C9A882` | Most Read 번호 |

### 6.3 대비 (WCAG AA)

**본문 4.5:1 · 큰 글자(24px+, 또는 18.66px+ Bold) 3:1.** 새 색을 넣을 때는 흰색이 아니라
**그 색이 실제로 놓이는 배경** 위에서 잰다 — `#64748B` 는 흰 배경에서 4.76:1 이지만
`--bg-surface`(`#FAF8F5`) 위에서는 4.49:1 로 AA 를 놓쳤다(2026-09-10 실측).

현재 토큰의 실측치. 배경은 **밝은 것부터 가장 어두운 것까지 세 면** — 라이트 `--bg` `#FFFFFF` /
`--bg-surface` `#FAF8F5` / `--bg-warm` `#F5F0EB`, 다크 `--bg` `#0A0A0A` / `--bg-surface` `#161412` /
`--bg-card` `#1E1E1E`. `--bg-warm` 을 빼놓으면 안 된다 — 라이트에서 가장 빡빡한 면이고,
홈 "A Letter Home" 카드처럼 **조건부로만 렌더돼 실측에 안 잡히는** 자리가 여기 있다.

| 토큰 | 라이트 | 다크 |
|---|---|---|
| `--text` | 17.40 / 16.42 / 15.37 | 18.07 / 16.77 / 15.22 |
| `--text-secondary` | 5.20 / 4.90 / 4.59 | 7.72 / 7.17 / 6.50 |
| `--text-tertiary` | 5.28 / 4.98 / 4.66 | 6.75 / 6.27 / 5.69 |
| `--accent` | 6.29 / 5.93 / 5.55 | 6.64 / 6.16 / 5.59 |
| `--mhj-brown` | 4.89 / 4.61 / 4.32 | 4.05 / 3.76 / 3.41 |
| `--mhj-brown-dark` | 2.23 / 2.11 / 1.97 | 8.87 / 8.23 / 7.47 |

`--text-secondary` 가 라이트 `--bg-warm` 위 4.59:1 로 **한계선에 가장 가깝다**. 이보다 옅은 회색을
새로 만들지 말고 `--text-tertiary`(4.66:1)를 쓴다 — 이름과 달리 tertiary 가 더 진하다.

`--text-tertiary` 는 **글자 전용이 아니다**: 블로그 인용문의 3px 왼쪽 선(`globals.css`), 메타 줄의
3px 점(`blog/[slug]/page.tsx`·`BlogLibrary.tsx`)도 이 토큰을 쓴다. 값을 바꾸면 그 장식의 무게도
함께 움직인다 — 같은 줄의 흐린 글자와 한 몸이라 의도된 동작이지만, 모르고 바꾸면 놀란다.

**투명도로 옅게 만들 때**: 알파는 대비를 그대로 깎고, `opacity` 는 **조상까지 곱해진다**.
푸터(`#111111`) 위 흰 글자 기준 `0.2 → 1.84:1`, `0.3 → 2.67:1`, `0.5 → 5.33:1`, `0.62 → 7.63:1`
— **0.5 아래로 내리지 않는다.** 잉크 색이 배경 밝기에 따라 뒤집히게 짜 놓아도 알파가 낮으면
소용없다: 9px 책등 날짜가 `--spine-ink` 를 쓰고도 `opacity: .55` 때문에 2.98:1 이었다
(`MagazineShelf.tsx`, 0.85 로 교정).

경계선·아이콘 같은 **비텍스트**는 3:1 이다(WCAG 1.4.11). 기준은 **경계 양쪽 모두** — 뉴스레터
입력칸 테두리는 섹션 배경 쪽 3.69:1 만 보고 통과로 읽었다가, 필드 안쪽 면 기준 2.90:1 로 미달이었다.

**브랜드 갈색**: `--mhj-brown`(`#8A6B4F`)은 테마를 따르는 배경 위에서는 10px 라도 통과한다
(흰 배경 4.89:1 · 네비 부제 실측 4.89:1). 문제가 되는 건 **테마를 따르지 않는 고정 배경**이다 —
푸터는 언제나 `#111111` 이라 라이트 테마에서 원색을 쓰면 3.86:1(28px 로고는 큰 글자라 통과,
10px 부제는 실패)이 된다. 그런 자리에서는 테마와 무관하게 밝은 쪽 `--mhj-brown-dark`(8.46:1)를 쓴다.

**측정 방법** — 판정 기준은 코드가 아니라 실제 픽셀이다. 스크립트는 서버를 띄우지 않으니
프로덕션 빌드를 먼저 올린다(**3003 은 dev 포트다 — dev 가 떠 있으면 끄고 시작할 것.
안 그러면 dev 를 재게 되고, dev 중 `npm run build` 는 CLAUDE.md 11 위반이다**):

```bash
npx playwright install chromium        # 최초 1회
lsof -ti:3003 | xargs kill             # dev 서버가 있으면
npm run build && npx next start -p 3003 &
node scripts/qa/audit-contrast.mjs     # 5화면 × 2테마 × 2뷰포트(1440 / 390)
```

CSS 클래스가 칠한 위반이 하나라도 있으면 **종료 코드 1**. `style=` 속성 쪽(본문 HTML·매거진 표지)은
코드로 0 을 만들 수 없어 세지 않는다. 사진·gradient 위의 글자는 색을 알 수 없어 재지 않고 건수만
보고한다 — **"위반 0" 은 "잰 것 중 0"이지 "화면에 결함이 없다"가 아니다.** hover·focus·빈 상태·
조건부 렌더는 아직 측정 밖이다.

### 6.4 색상 사용 원칙

- **사진의 색감이 유일한 컬러** — UI는 무채색 기반
- 인디고 액센트(`--accent`)는 **AI Insight 버튼, 인터랙티브 요소에만** 사용
- 카테고리 라벨에 컬러 뱃지 사용 금지 → 회색 텍스트로 통일
- Featured 등 상태 표현은 **텍스트 라벨** 또는 **미세한 보더**로
- 색상 하드코딩 금지 (CLAUDE.md 5). 예외는 매거진 지면 — `docs/MHJ_MAGAZINE_DESIGN_BIBLE.md`

## 7. 간격 리듬 (8px 그리드)

모든 간격은 8의 배수로만 사용한다.

- 8px — 아이콘과 텍스트 사이, 아주 작은 gap
- 16px — 카드 내부 패딩, 작은 요소 간격
- 24px — 카드 간 gap, 중간 간격
- 32px — 섹션 내부 요소 간격
- 48px — 소형 섹션 간 여백
- 64px — 중형 섹션 간 여백
- 96px — 대형 섹션 간 여백 (기본)
- 128px — 페이지 최상단/최하단 여백

clamp 사용 시에도 상한/하한 모두 8px 배수여야 한다.

## 8. 모서리 (Border Radius)

### 8.1 규칙

| 요소 | radius | 비고 |
|------|--------|------|
| **블로그 카드** | 12px | 32~50px 금지 |
| **버튼** | 8px | pill(999px)은 특수 버튼에만 |
| **이미지** | 8px | 카드 안 이미지 |
| **모달/패널** | 16px | 대형 UI 요소 |
| **뱃지/태그** | 4px | 작은 라벨 |
| **서가 아이템** | 0px | 책 느낌 유지 |

### 8.2 원칙

- **32px 이상의 radius는 사용하지 않는다**
- 40~50px radius는 SNS/앱 스타일 → 에디토리얼과 맞지 않음
- 예외: 프로필 이미지 (원형 50% 허용)

## 9. 호버 & 트랜지션

### 9.1 카드 호버

```css
/* ❌ 금지 — 과도함 */
transform: translateY(-16px);
box-shadow: 0 30px 60px rgba(0,0,0,0.15);

/* ✅ 허용 — 절제 */
.card:hover {
  opacity: 0.92;
  transition: opacity 0.3s ease;
}
/* 또는 */
.card:hover .card-image {
  transform: scale(1.02);
  transition: transform 0.5s ease;
}
```

### 9.2 트랜지션 기본값

```css
transition: all 0.3s ease;
```

- cubic-bezier(0.16, 1, 0.3, 1)는 **서가 전용**으로만 사용
- 일반 UI 요소는 ease 또는 ease-out

### 9.3 애니메이션 원칙

- 페이지 로드 시 fade-in: opacity 0→1, 0.5s — 허용
- 스크롤 트리거 slide-up: **사용하지 않는다** (과도한 움직임)
- stagger 딜레이: **사용하지 않는다** (카드가 순서대로 튀어오르는 것은 게임 느낌)

## 15.5 접근성 (2026-09-10 W6-B)

### 클릭되는 것은 진짜 요소로 만든다

**`<div onClick>` 을 쓰지 않는다.** 이동하면 `<Link href>`, 동작하면 `<button>`.
`role="link" tabIndex={0}` + `onKeyDown` 으로 흉내 내는 것도 마찬가지다 — 진짜 `<a href>` 는
Enter·가운데클릭·새 탭·컨텍스트 메뉴·크롤러를 전부 공짜로 준다.

⚠️ **`<a>` 는 Space 로 활성화되지 않는다**(Space 는 페이지를 스크롤한다). Space 로 눌려야 하는 것은
`<button>` 이다. 그래서 "이동이냐 동작이냐"로 갈라야지, 둘을 바꿔 쓰면 키보드 계약이 달라진다.

2026-09-10 이전 `/blog` 의 글 카드 다섯 종류가 전부 `<div onClick={router.push}>` 이었다.
결과는 **키보드로 어떤 글도 열 수 없었고, HTML 에 `<a href="/blog/…">` 가 0개**였다 —
검색 엔진 눈에 블로그 허브가 어느 글로도 링크하지 않는 페이지였다는 뜻이다.
`scripts/qa/audit-a11y.mjs` 가 이제 그 링크 수를 세어 회귀를 막는다.

### 랜드마크는 겹치지 않게

- 페이지 안에서 `<main>` 을 새로 열지 않는다 — `app/(public)/layout.tsx` 가 이미 하나 연다.
- `<main>` 안의 `<aside>` 는 랜드마크가 중첩된다. 사이드바는 `<div>` 로.
- `<nav>` 가 한 페이지에 둘 이상이면 **각각 `aria-label`** 을 준다(주 메뉴 / Breadcrumb / 이전·다음).
- 여닫이 패널에 `role="region"` 을 붙이지 않는다 — 문항 수만큼 랜드마크가 생긴다.
  버튼의 `aria-expanded`·`aria-controls` 로 충분하다.
- 모든 콘텐츠는 랜드마크 **안**에 있어야 한다. `<main>` 밖에 섹션을 두면 안 된다.

### 상태를 말해 주는 이름

토글 버튼의 `aria-label` 을 고정 문자열로 두지 않는다 — 메뉴가 열린 뒤에도 "메뉴 열기" 라고
읽어 준다. `aria-expanded` 와 함께 라벨도 상태를 따라가게 한다.

### 숨기기

포커스를 받아야 하는 것을 `display:none` / `visibility:hidden` 으로 숨기면 **포커스 자체를
못 받아 죽는다**. 본문 바로가기 링크(`.skip-link`)처럼 화면 밖으로 밀었다가 `:focus` 에 끌어온다.

### 클릭 추적 (2026-09-11 W6-C)

클릭을 재려면 `onClick={() => trackEvent(...)}` 대신 **`data-track` 속성**을 단다:

```tsx
<Link href={href} data-track="pillar_click" data-track-pillar={id}>…</Link>
```

- `AnalyticsShell`(안의 `OutboundLinkTracker`) 하나가 전역 위임으로 받아, GA4 이벤트와 1st-party
  `page_events`(`event_type='click'`, `meta.name` = 이벤트명)에 **같은 이름**으로 남긴다. (public) 레이아웃과
  루트 404 가 같은 셸을 쓴다 — 새 분석 도구도 **셸에** 넣는다(레이아웃에만 넣으면 루트 404 가 빠진다).
- 속성만 달면 되므로 **서버 컴포넌트의 `<Link>` 에도 붙는다**(홈 기둥 셀). 클릭을 재려고 `'use client'` 로 바꾸지 않는다.
- 파라미터는 `data-track-<이름>`. 여러 단어는 **밑줄**(`data-track-blog_id`) — 하이픈은 dataset 이 camelCase 로 바꿔
  GA 의 snake_case 와 어긋난다.
- 폼 제출처럼 클릭이 아닌 곳은 `lib/first-party.ts` 의 `trackClick(name, params)` 를 직접 부른다(같은 모양으로 쌓인다).
- 외부 링크(outbound)는 속성 없이 자동이다. 내부 판정은 "지금 호스트와 같은가(www 무시)" — `app.mhj.nz` 는 외부다.
  단 **`data-track` 이 달린 외부 링크는 이름 있는 이벤트 하나로만** 남는다(`link_url` 파라미터가 붙는다) —
  outbound 를 또 보내면 한 번의 클릭이 GA 와 page_events 에 두 번 세어진다.
- 파라미터 값은 전부 **문자열**로 간다(dataset). 방문자가 친 자유 입력(검색어 등)은 싣지 않는다 —
  1st-party `page_events.meta` 에 그대로 쌓인다.

### 측정

```bash
lsof -ti:3003 | xargs kill             # ⚠️ 3003 은 dev 포트다. dev 가 떠 있으면 먼저 끌 것 —

```

둘 다 위반이 있으면 종료 코드 1 이고, 주간 `site-audit` ⑫·⑬으로 돈다.

**"위반 0" 이 "결함이 없다" 는 아니다.** 이 검사가 구조적으로 못 보는 것:
- **React 의 `onClick`** — `<div onClick>` 문제는 axe 가 아니라 `<a href>` 를 직접 세어 찾았다.
  `/gallery` 는 감사 대상이면서도 "위반 0" 이었는데, 사진 334장이 키보드로 안 열렸다.
- **감사 목록에 없는 경로** — `/magazine/[id]`, `/blog/tag/…`, 404·에러 화면.
- **열어야 보이는 것** — 모달·오버레이. 모바일 메뉴·검색·FAQ 세 가지만 열어 본다.
- **`aria-*` 가 상태를 따라가는지** — axe 는 `aria-expanded` 가 붙어 있는지만 보지,
  그 값이 실제 상태와 맞는지는 모른다.
