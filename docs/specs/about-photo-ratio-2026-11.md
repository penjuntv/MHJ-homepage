# 설계서 — 사진은 올린 비율 그대로 (About 먼저, 2026-11-10)

> 근거: PeNnY 2026-11-10 — "일부러 세로로 긴 사진을 쓴 건데(높은 나무와 하늘을 보여 주려고) 사진을 자르면 의미가 퇴색된다. 사진은 다 일부러 사이즈 맞게 올리는 것이니, 크롭 기능을 넣어서 업로드 이전에 사진 크기를 확정하고, 확정된 사진에 맞춰 유동적으로 텍스트 위치를 조절하게 하는 게 맞다."
> 결정(같은 날 질문 4개): ① #201 로 모바일 4:3 자르기 먼저 되돌림 ② About 사진 6장부터 ③ 세 딸은 같은 비율(3:4)로 크롭 ④ 기존 사진은 원본 비율로 바로(비율 2줄 DB 기록 — 승인 후 실행).

## 0. 실측 (운영, 고치기 전)

| 사진 | 원본(sharp) | 화면 틀 | 잘림 |
|---|---|---|---|
| 가족사진(Who we are) | 3024×4032 세로 3:4 | 4:5 | 6% |
| 무지개(Vision) | 1600×1200 **가로 4:3** | 4:5 | **40%** |

모든 사진을 4:5 틀에 `object-fit: cover` 로 넣어 왔다. 관리 화면 3곳(설정 · 페이지 편집 · 가족)은 크롭 없이 바로 올렸다. 크롭 모달(`ImageCropModal`)은 블로그·매거진·뉴스레터에만 연결돼 있었다.

## 1. 바꾸는 것

| 곳 | 무엇 |
|---|---|
| `lib/image-ratio.ts`(신규) | `ratioKey()` · `cssRatio()`("3024/4032" → "3024 / 4032", 없으면 4:5) · `measureImage()`(브라우저, EXIF 회전 반영) · 크롭 선택지 `PHOTO_ASPECTS` · 세 딸 `DAUGHTER_ASPECT` 3:4 |
| `components/admin/ImageCropModal.tsx` | 선택 props: `aspectOptions` · `allowSkip`(false 면 "원본 그대로" 숨김) · `note`(안내 한 줄). 기존 사용처(블로그 등)는 그대로 |
| 관리 — 설정 · 페이지 편집 | 파일 고르면 크롭 창(원본 그대로 · 3:4 · 4:5 · 4:3 · 1:1 · 16:10 · 자유) → 올린 사진 가로·세로를 `<키>_ratio` 에 함께 저장. URL 을 손으로 바꾸거나 지우면 비율도 비움 |
| 관리 — 가족 | 세 딸: 크롭 3:4 고정(원본 그대로 없음), 미리보기 틀도 3:4. 부모: 자유 |
| 공개 About | 가족사진·무지개 틀 = 저장 비율(없으면 4:5) · Yussi = 800/1100 상수(`YUSSI_IMAGE_RATIO`) · 세 딸 = 3:4. 2열 그리드는 `alignItems: center` 그대로 — 글이 사진 높이에 맞춰 가운데로 움직인다 |
| DB(승인·실행 완료 2026-11-10) | `site_settings` 에 `about_who_image_url_ratio=3024/4032` · `about_image_url_ratio=1600/1200` 두 줄. 되돌리기 = 두 줄 삭제(옛 코드는 이 키를 읽지 않음) |

## 2. 남는 일

- **Hyun 사진 다시 올리기(가족 몫)**: 가로 4:3 원본이라 3:4 틀에서 잘린다. 관리 화면 → Family → Hyun "사진 변경" 에서 3:4 로 크롭해 올리면 0%.
- 다른 관리 화면(갤러리 · 홈 사진 · 매거진 · 블로그 등)으로 같은 방식 넓히기 — About 확인 뒤.
- Yussi 사진은 관리 화면이 없는 코드 상수다. 바꿀 때 `YUSSI_IMAGE_RATIO` 도 같이 바꾼다.
