> 개인정보: 이 문서와 답에 아이 실명·이메일·키 값을 쓰지 않는다. 계정은 UUID 앞 8자로만 부른다.

안녕하세요, MHJ 홈페이지 세션입니다. PeNnY 가 오늘(10/24) YuStudy DB 분리를 다시 결정했습니다. 일정은 **~11/15 확인만 → 11/16~22 전환 → 12월 첫 주 홈페이지 정리**입니다. 전환 전에 아래 일곱 가지를 확인해 주세요. 사실은 저장소·DB 에서 직접 확인해 답해 주시고, 결정이 필요한 것은 추천안을 붙여 주세요.

**1. 새 가입을 꺼도 되나요? (가장 급함 — 답이 오기 전엔 끄지 않습니다)**
Supabase 대시보드 Authentication → Sign-ups 를 끄면 새 auth 계정을 만들 수 없게 됩니다(기존 계정 로그인은 유지).
- YuStudy 앱에서 `supabase.auth.signUp`(또는 OTP·매직 링크로 새 사용자가 생기는 흐름)을 쓰는 곳이 있나요? 부모 회원가입 화면, 아이 프로필 추가, 초대 등.
- 아이 프로필 추가는 auth 계정을 새로 만드나요, 아니면 `profiles` 행만 만드나요?
- QA·테스트용으로 계정을 만드는 스크립트나 엣지 함수(`qa-create-user` 등)가 지금도 쓰이나요?
- 꺼도 되면 "꺼도 됨", 안 되면 무엇이 깨지는지와 대안(초대만 허용, 이메일 도메인 제한 등)을 알려 주세요.

**2. 9/14 이후 생긴 계정 1개가 누구인가요?**
auth 사용자 `5d3106ee…` — 2026-09-20 20:26(NZ) 생성, 이메일 가입·확인됨, 로그인 기록 있음. YuStudy 쪽에서 아는 계정(가족·테스트)인가요? 모르면 "모름"으로 답해 주세요. 가족이 아니면 분리를 11/15 전으로 앞당깁니다.

**3. 9/14 "남은 일"이 어떻게 됐나요?**
- 3단계 사용처별 비밀 키 발급: 했나요? YuStudy 가 지금 쓰는 키 종류(`service_role`·secret·publishable)와 놓인 곳(Vercel env·로컬·스크립트)을 키 값 없이 목록으로.
- 4단계 DDL 시간대(NZ 01~05시): 홈페이지 쪽 조회로는 9/14 이후 YuStudy 마이그레이션 36건 중 4건만 그 시간대였습니다(마이그레이션 version 시각 기준). 맞는지, 그리고 전환까지 이 규칙을 지킬 수 있는지.

**4. Phase 0(준비) 언제 시작하나요?**
계획서 Phase 0 의 기준선을 다시 재야 합니다 — 9/13 이후 `public` 테이블이 67→75 로 늘었습니다(YuStudy 새 테이블 포함 추정). 새 테이블·함수·트리거·버킷·RLS 를 이전 목록에 반영하고, 전환 전 **DDL 동결**을 언제부터 걸 수 있는지 알려 주세요.

**5. 전환 창은 언제가 좋나요? (11/16~22 안에서)**
원안(D3)은 "평일 오전 학교 시간", 위원회 판결은 "새벽 한산 시간대"입니다. 아이들이 앱을 안 쓰는 시간과 크론 시각(03:00·12:00 UTC)을 고려해 추천해 주세요. YuStudy 는 30~60분 중단 + 전원 재로그인 1회입니다.

**6. 롤백을 어떻게 하나요?**
판결안: 관찰 기간(7~14일)엔 옛 표가 남아 있으니 문제가 생기면 Vercel 환경변수를 옛 프로젝트로 되돌린다(그 사이 새 학습 기록은 잃을 수 있음). 이 방식이 YuStudy 에서 실제로 되는지(Capacitor `server.url` 원격 로드로 앱 재배포 없이), 잃어도 되는 기록 범위가 어디까지인지 알려 주세요.

**7. 전환 뒤 홈페이지 정리(Phase 4, 12월 첫 주)에 넘겨줄 것**
전환·관찰이 끝나면 "옛 프로젝트의 YuStudy 객체를 지워도 된다"는 신호를 이 세션에 보내 주세요(지울 테이블·함수·트리거·버킷 목록과 함께). 홈페이지 세션은 그 신호 전에는 YuStudy 객체를 건드리지 않습니다.

답은 이 세션에 메시지로 보내 주시거나, YuStudy 저장소 문서에 남기고 경로를 알려 주세요. 감사합니다.
