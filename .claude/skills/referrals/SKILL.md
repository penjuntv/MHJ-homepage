# 1:1 전달 — 독자가 독자에게

> 거르는 질문 하나: **"이 일이 끝나면 mhj.nz 에 새 사람이 도착하는가?"**
> 아니면 하지 않는다 (`feedback_exposure_scope_lock`).

## 먼저 숫자 — 왜 이 스킬이 1:1 에 집중하나

결론: **작동이 확인된 경로는 사람이 사람에게 직접 보내는 것 하나뿐이다.**

| 경로 | 실측 (2026-09~10) |
|---|---|
| 유씨의 1:1 개인 전달 (WhatsApp) | **1명에게 보냄 → 1명이 40초 읽고 구독** (2026-09-21) |
| 유튜브 @mhj_nz | 구독자 117, 커뮤니티 탭 없음 — 링크 자리는 영상 설명란뿐 |
| 인스타 @mhj_nz | 팔로워 13 — 게시물·스토리 6세션 전부 체류 5초 미만 |
| 페이스북 | 페이지가 아니라 개인 프로필, 친구 0 — 도달이 구조적으로 0 |
| 뉴스레터 Mairangi Notes | 16명 |

그런데 1:1 에는 **천장**이 있다. 유씨가 "소개할 만큼 친한 친구는 더 없다"고 했다 (2026-09-23).
그래서 이 스킬의 진짜 목표는 이것이다:

> **유씨 한 사람이 보내는 구조 → 읽은 사람이 다음 사람에게 넘기는 구조.**
> 받은 사람이 "이거 ○○ 엄마한테도 보내야겠다"고 느끼고, 그걸 10초 안에 할 수 있게 만든다.

근거 문서: `docs/EXPERIMENT-NOW.md` §3-2~3-4, `docs/PLAN-distribution-2026-09.md` §1~§4, 메모리 `project_owned_channel_reach`.

## 시작 전에 확인할 것

이미 대화나 문서에 있으면 묻지 않는다. 빠진 것만 묻는다.

1. **어느 글인가** — 슬러그. 정보형(학교·성적표·정착)인지 에세이인지.
2. **누가 보내나** — 유씨 · PeNnY · 독자(받은 사람이 다시 보냄).
3. **받는 사람의 상황** — 국적이 아니라 상황으로 적는다. 예: "곧 아이를 데려오는 엄마", "첫 성적표를 받은 부모".
4. **언어와 메신저** — 한국어/영어, 카톡/WhatsApp/문자. 유씨의 실제 연결망은 **대면·영어권·개인 관계**다. 카톡 단톡방은 유씨 연결망에 거의 없다.
5. **그 사람이 전에 물어본 것** — 있으면 문안의 첫 줄이 된다. 가장 강한 재료다.

## 보상형 추천 프로그램은 맞지 않는다 (정직하게)

원본 스킬의 절반은 SaaS 용이다. MHJ 에는 버리는 이유가 분명하다.

- **보상(크레딧·할인·굿즈·단계별 선물)** — 줄 상품이 없다. 무료 잡지에 보상을 붙이면 "왜 보냈는지"가 정보에서 보상으로 바뀐다. 받는 쪽 신뢰가 먼저 깨진다.
- **제휴(affiliate)·수수료** — 팔 것이 없다. 계약·정산·사기 방지 장치 전부 해당 없음.
- **리뷰 플랫폼(G2·Trustpilot·구글 리뷰) 요청** — 해당 플랫폼이 없다.
- **추천 코드·순위표·"3명 추천하면"** — 가족 잡지 톤("따뜻하되 세련된")과 맞지 않는다.

남기는 것은 원본의 **비보상 장치**다: 알맞은 순간에 묻기 · 미리 써 둔 메시지 · 한 번에 보내기 · 받은 사람의 도착 경험 · 측정.
보상 대신 MHJ 가 줄 수 있는 것은 **"보낸 사람이 친구에게 도움이 됐다"는 느낌**과 **질문에 답해 주는 것**이다.

## 전달 고리

```
계기(누군가 그 답이 필요해짐) → 전달(복사·붙여넣기 한 번) → 도착(첫 화면에 답) → 답장·되물음 → 다음 전달
```

원본의 고리는 "계기 → 공유 → 전환 → 보상"이다. MHJ 판은 **보상 자리에 "대화"가 들어간다.**
받은 사람이 되물으면, 그 질문이 다음 글감이자 다음 전달 계기가 된다.

## 1단계 — 전달 계기 (언제 사람이 자연스럽게 글을 보내나)

원본: "가치를 막 느낀 순간에 묻는다." MHJ 판: **누군가 그 답이 지금 필요해진 순간.**

| 계기 | 철 | 맞는 글 (예) |
|---|---|---|
| 친구·지인이 오클랜드로 온다 / 아이를 데려온다 | 연중 | starting-school-in-new-zealand |
| 입학·학년 배정 | 11~2월 | starting-school-in-new-zealand |
| 개학 준비·도시락 | 1~2월 | (해당 글이 있으면) |
| 중간 성적표가 나왔다 ("consolidating 이 뭐야?") | 6~7월 | how-to-read-a-mid-year-report |
| 고학년·NCEA 제도 변경 소식 | 발표 시 | ncea-is-changing-no-more-levels-no-more-credits |
| 학교에서 Keeping Ourselves Safe 안내문이 왔다 | 텀 시작 | (해당 글) |
| 텀 방학 — 아이와 갈 곳 | 텀 방학 전 1주 | 도서관·나들이 글 |
| 단톡방·대면에서 누가 바로 그 질문을 했다 | 그때 | 질문에 맞는 글 하나 |

- **철보다 2~3주 앞서** 키트를 준비한다. 계기가 온 뒤 만들면 늦다.
- 글을 고를 때 기준은 "우리가 홍보하고 싶은 글"이 아니라 **"그 사람이 물은 것에 답하는 글"**이다. 2026-09-21 의 성공도 "전에 물어본 사람에게, 그 질문의 답"이었다.
- 슬러그는 실제로 있는지 사이트에서 확인한 뒤 쓴다. 표의 "(해당 글)"은 추측으로 채우지 않는다.

## 2단계 — 전달 장치 (마찰을 없앤다)

원본 순위(제품 안 공유 > 개인 링크 > 이메일 > SNS > 코드)를 MHJ 에 옮기면:

1. **사람이 직접 보내는 개인 메시지** — 확인된 유일한 경로. 문안 + 링크를 Claude 가 완성해서 준다.
2. **받은 사람이 그대로 다시 보낼 수 있는 문안** — 1번 메시지 안에 "필요한 분 있으면 이대로 보내셔도 돼요" 한 줄과 함께.
3. **글 안의 "이 글이 필요한 사람" 한 줄** — 읽은 사람이 떠올릴 얼굴을 정해 준다 (아래).
4. **뉴스레터의 전달 한 줄** — "이번 호가 필요한 분께 그대로 전달해 주세요." (→ newsletter-composer)
5. **사이트 공유 버튼** — 이미 있지만 클릭 0 (`blog_share`, 2026-09-02~19). 버튼이 고리를 만들지 않는다.

### 마찰 규칙

- **한 메시지에 링크 하나.** 글 두 편이면 메시지 두 개.
- **복사할 덩어리는 따로 보낸다.** 카톡은 메시지 하나를 통째로 복사한다. 설명과 섞이면 설명까지 붙여넣어진다 (`docs/kit-1b-kakao-2026-09-22.txt` 의 교훈 — `[설명]`/`[복사용]` 분리).
- **링크는 글로 바로.** 홈으로 보내지 않는다. 짧은 주소(`/yt`·`/ig`·`/fb`)는 프로필 같은 고정 자리용이고 홈으로 간다.
- **링크 모양이 지켜졌는지 확인한다.** 2026-09-21 전달은 UTM 링크를 썼다는데 기록은 `direct` 였다. 원인은 **미확인**. 다음 전달 때는 보낸 메시지 캡처를 한 장 받는다.

### 문안 원칙 (`EXPERIMENT-NOW` §1 에서 검증된 형태)

1. 그 사람이 물었던 것을 먼저 꺼낸다.
2. 이 글이 답하는 것 한 줄.
3. 링크.
4. 되물을 여지 ("학교마다 다를 수 있으니 다르면 알려 줘요").

- 홍보 문구·"구독해 주세요"는 넣지 않는다. 구독 얘기는 보내는 사람이 **자기 말로 한 줄**이면 충분하다.
- 받는 사람의 언어로 쓴다. 영어권 관계면 영어.
- 아이는 Min / Hyun / Jin 으로만.

템플릿과 키트 형식: [references/share-kit-template.md](references/share-kit-template.md)

### "이 글이 필요한 사람" 한 줄

글마다 **읽는 사람이 떠올릴 한 사람**을 정해 주는 문장이다. 전달 문안의 첫 줄로도, 글 끝·뉴스레터에도 쓴다.

- 형식: `이 글이 필요한 사람 — <상황>인 <사람>.`
- 예: `이 글이 필요한 사람 — 내년 초 아이를 NZ 학교에 처음 보내는 부모.`
- 예: `Who this is for — a parent holding their first NZ school report and wondering what "consolidating" means.`
- 국적이 아니라 **상황**으로 쓴다. 실제로 온 사람은 "중국에서 아이를 데려오는 엄마"였다.
- 글 본문에 넣는 것은 본문 수정이다. **Claude 는 문장을 제안만 하고, 넣을지는 유씨·PeNnY 가 정한다.**

## 3단계 — 받은 사람의 도착

원본: "추천받은 사람의 착지 경험을 다듬는다." MHJ 판:

- 받은 사람은 **휴대폰 메신저 안 브라우저**로 연다. 첫 화면에 그 질문의 답이 보여야 한다 (유씨에게 보낸 글쓰기 안내의 "네 층" — 1층 제목=질문, 2층 첫 두세 줄=답, 3층 우리 집 이야기, 4층 FAQ. `docs/kakao-yussi-2026-09-24.txt`).
- 한국어로 보내는데 글이 영어뿐이면, 문안에 핵심 답을 한국어 한두 줄로 먼저 적어 준다.
- 보낸 사람의 이름이 신뢰의 전부다. 문안은 보낸 사람 말투여야 한다. 잡지 홍보 말투면 신뢰가 사라진다.
- 도착 화면 자체를 고치는 일(제목·요약·FAQ)은 이 스킬 범위가 아니다 → 필요하면 한 줄 메모로 남긴다.

## 4단계 — 보상 대신 대화

- 받은 사람이 답장·질문을 하면, 보낸 사람이 답한다. 모르면 유씨가 답을 만들어 준다.
- 반복되는 질문은 **다음 글감**이고 **다음 전달 계기**다. `docs/EXPERIMENT-NOW.md` 기록표에 적는다.
- 받은 사람의 말을 글·SNS·뉴스레터에 인용하려면 **본인 허락**이 먼저다. 이름·나라·아이 정보 없이, 허락받은 문장 그대로. 여러 사람 말을 한 문장으로 합치지 않는다 (원본 리뷰 재사용 규칙).

## 측정

### UTM 규칙 (지금 수집 코드 기준 — `lib/traffic-source.ts`)

| 상황 | 링크 |
|---|---|
| 1:1 개인 메시지 (메신저 상관없이) | `?utm_source=direct_share&utm_campaign=<글슬러그>` |
| 카톡 단톡방·오픈채팅에 올림 | `?utm_source=kakaotalk&utm_campaign=<글슬러그>` (별칭 있음 → social) |
| WhatsApp 그룹에 올림 | `?utm_source=whatsapp&utm_campaign=<글슬러그>` (별칭 없음 → referral 로 기록) |
| 뉴스레터 | `?utm_source=newsletter&utm_campaign=<호>` |

- 값은 소문자·`[a-z0-9._-]`·40자로 정리된다. 한글·공백을 넣지 않는다.
- `utm_content` 는 지금 **기록되지 않는다.** 보낸 사람을 나눠야 하면 별도 결정이 필요하다 — 임의로 source 값을 늘리지 않는다.
- **한계**: 받은 사람이 같은 링크를 또 보내면 그 다음 사람도 `direct_share` 로 찍힌다. 몇 번째 전달인지는 링크로 구분할 수 없다. 2차 전달을 따로 세려면 사이트 쪽 코드가 필요하다 → 범위 밖, 제안만.

### 구독까지 이어졌는지

- 지금 구독 기록(`subscribers.source`)은 **어느 폼**(예: `blog_mid`)만 남기고 **어느 채널**은 안 남긴다.
- 채널을 남기는 지시서가 있다: `docs/HANDOFF-subscribe-utm-2026-09-27.md`. 여기서는 참조만 한다 (구현은 이 스킬의 일이 아니다).
  - 참고: 그 지시서의 허용 목록 예시에는 `direct_share` 가 없다. 구현할 때 함께 넣어야 1:1 구독이 `other` 로 뭉개지지 않는다.
- 그 전까지는 같은 시간대의 세션과 구독을 손으로 맞춰 본다 (2026-09-21 사례처럼).

### 무엇을 보나

- **외부 유입 세션** — 원수치와 **체류 5초 이상**, **2페이지 이상**을 나란히. 링크를 새로 뿌리면 플랫폼의 자동 점검 방문이 사람처럼 찍힌다.
- **구독자 순증.**
- **구체적 반응** — 답장·되물음·"다른 사람에게도 보냈어요".
- 스냅샷: `node --env-file=.env.local scripts/report-traffic-snapshot.mjs --write`

원본의 K-factor(초대 수 × 전환율)는 MHJ 표본으로 계산하지 않는다. 대신 한 줄로 적는다:
`보낸 사람 수 → 읽은 사람 → 구독 → 다시 보낸 사람`. 표본 1~3 이면 통계가 아니라 **"이 글이 실제로 도움이 됐나"**를 확인하는 것이다.

**성과가 아닌 것**: 만든 키트 수, 보낸 메시지 수, 공유 버튼 노출 수.

## 산출물 — Claude 가 만드는 것

**전달 키트 1개** (글 1편, 보내는 사람 1명 기준):

1. 이 글이 필요한 사람 한 줄 (한/영)
2. 보내는 사람용 문안 — 언어별 1개씩, `⟨ ⟩` 안만 고치면 되게
3. 받은 사람이 다시 보낼 수 있는 짧은 문안
4. UTM 링크 (복사용 메시지로 분리)
5. 보낸 뒤 알려 줄 것 3가지 — 보낸 날짜 · 메시지 캡처 1장 · 답장 유무
